MC Training master audit

The engineering underneath is strong: 52 static gates pass, the Modality Matrix meets every structural rule I could render, and the storage layer survives concurrency, crashes and corruption. The problems are at the seams. Re-rendering a page erases the session it mirrors, the progression engine judges sessions too generously, and sheets don't behave like an app's. Three of the defects cost an athlete data.

Key takeaways

  • Session state is copied from the screen. Anything that re-renders the cards, such as a week tab, erases the session record. All 7 of 7 tabbed engines tested do it.
  • The progression engine is too generous. It targets the bottom of rep ranges, judges pyramids against their last set, and counts partial sessions as wins.
  • Program content mostly matches its rules. The Modality Matrix passes all structural checks. Strength & Supersets' deload week and High-Volume's headline claim don't match their content.
  • Sheets aren't app-grade. Of 11 overlays, 1 closes on Escape and 1 locks the page behind it, and the phone's Back gesture leaves the page.

Decisions you made

  • Fix data integrity first.
  • Progression: per-set, top of range. Partial sessions hold.
  • Increments: follow the ×0.5 spec, and tighten the big-lift pattern.
  • Deload: a real deload, cutting a third to half of working sets and capping intensity.
  • Back gesture: one shared sheet and navigation contract.
  • Retire the custom-workout Finish button. Deletes apply everywhere. All four design tracks are in scope.

Top 5 pain points

Ranked by harm × reach. Each journey was driven in headless Chromium at 390 and 320px, logging real sets through the real modules. A "confirmed" chip means I watched it happen.

1

Peeking at next week erases today's workout

Critical · session lossConfirmed on 7 / 7 engines

I tapped W2 to see what's coming, went back to W1, and every tick was gone. Reloading didn't bring them back.

mm-p1 · log 2 sets, then…Session recordAfter reload
Reload only (control)mm-p1 · 2 sets2 / 46
W1 → W2 → W1, then reloaddeleted0 / 46
Reach
mm-p2, kitchen-sink, iron-engine, hv-block, cat-strength, psu-strength and bro-split all wiped the record on a tab round trip. Every program with week, phase or cycle tabs is affected.
Root cause
mc-session.js's save() rebuilds the session from the ticks currently on screen. The week change re-renders the cards without ticks, so save() concludes nothing is in progress and runs delete s0[PID]. The sets survive in mc_setlog_v1, so a finished workout still saves them, but with setsChecked: 0. The ticks, the dashboard resume banner, crash recovery and the elapsed clock are lost.

Custom workouts save zero sets

Critical · data lossConfirmed by driving

3

"Add weight" arrives before it's earned

High · every sessionReal engine, test vectors

I only got the bottom of the rep range, or quit after two sets, and the app still told me to go heavier.

Last sessionShould beEngine said
4×10-12 · did 10,10,10,10repeat (top is 12)progress

Root cause
topRep() in mc-suggest.js returns the floor of a range and the last rep of a pyramid. classifySession() compares every set to that one number and ignores sets that weren't logged. computeIncrement() sets every leverage-assisted lift to a flat 2.5 lb instead of halving the barbell step, which affects 18 cable, machine and plate-loaded big lifts (corrected in Phase 3 from an earlier count of 25). The existing test asserts that behavior, so it passes.
4

Deleted workouts come back

High · signed-in usersReal merge function

I deleted a test workout. The dialog said it can't be undone, and the next time I opened the app it was back.

Root cause
mergeWorkoutLog() is a pure union that ignores the last-synced copy, and deletes are never recorded. Running it with local [A] against cloud [A, B] gives [B, A], and "Clear All" comes back the same way. The tested mergeArrayByIdTs in the same file already handles deletions for other stores.
5

Medium · every screen11 overlays measured

Proactive design & usability

Design upgrades

Give the PR its moment

Micro-interaction

The best moment in a session currently looks like every other set. When a logged weight beats the lift's local best, mark the row gold with a "PR" chip, use a distinct double-pulse haptic, and announce "New personal record, 70 pounds" through the existing timer live region. The local best is already in mc_setlog_v1, so this needs no network and works signed out.

One sheet contract for every overlay

Interaction

One small shared module, which every overlay calls when it opens and closes, handles role="dialog" and aria-modal, moves focus in and returns it, closes on Escape, locks the page behind (overflow:hidden plus overscroll-behavior:contain) and pushes a history entry so Back closes the sheet. Opening a day pushes an entry too. Eleven hand-built overlays converge on one behavior.

Let the next set's number lead

Dark & light contrast

The suggested weight is the most useful number mid-set, and in light mode it's the least legible. Keep it italic and dashed, at a readable ink:

185today · 1.47:1185proposed --ink-6 · 5.23:1

Use color only where it means something

Visual language

Gold marks what's active or actionable. Red means failure or destruction. Everything else is ink. Make the red prescription pill, the blue active week tab and the builder's teal and sky-blue labels neutral. Keep true black (--ink-0) as the OLED ground, and move the bottom nav's cool rgba(8,10,16) onto the warm ramp.

Calm the session screen

Hierarchy

Show one rest readout instead of three. Move Replace and Reorder into ⋯, which frees a 44px row on every open card. Mark finished values with the tick and a row tint, not strikethrough. Keep the tempo for the Pos 4 TUT anchor visible as a badge in the card header rather than behind ⓘ.

A type floor of 11px

Typography

Stats has 36 text nodes under 11px, Programs 19 and Nutrition 17. Map those labels onto the existing --fs-* scale with an 11px minimum, and widen letter-spacing on uppercase labels instead of shrinking them.

Remember where people were

State

Put the dashboard tab in the URL and restore each tab's scroll. Remember the History tab and the Stats Recovery/Volume choice per device in localStorage, declared in store-registry.json. Keep a workout-builder draft so a half-picked workout survives leaving the page.

Extend the token gate before migrating

Architecture

Teach check-design-tokens.js to read CSS strings in 30 JS modules (119 slate values), inline page styles (446) and rgba(). Seed it as a per-file ratchet, then migrate the session surface first, measured by luminance.

Replace native dialogs

Consistency

alert() on custom finish, confirm() on deletes, Max Out retries and Replace all break the app's visual language and can't be styled for dark mode. Route them through the new sheet contract.

Method & limits

What was run, and what wasn't

Run in this audit

  • All 52 static gates. Browser gates against a local server: journey, concurrency, store resilience, crash recovery, identity, PR scope, restore fidelity, contrast in light and dark, and a 38-page smoke test.
  • mc-suggest, mc-log-read, mc-maxout and mc-classify run in Node against test vectors and all 580 catalog names.
  • The real TMR.parseSeconds run in-page over every rest string in the tree.
  • Rendered prescriptions for every week × day of mm-p1, iron-engine, hv-block, kitchen-sink and cat-strength (106 renders).
  • Week-tab round trips on 7 engines, 11 overlays, 28 screens at 390 and 320, state round trips and a PR probe.
  • Supabase security and performance advisors, and the weekly check-in workflow log.

Not verified here

  • Real iOS and Android devices, the installed PWA and true offline. The service worker only runs on the production origin.
  • Live sign-in and two-device sync. Supabase traffic was blocked in the browser runs.
  • The Back-gesture finding uses browser history. An iOS edge swipe in an installed PWA should behave the same, but that's unconfirmed.
  • Import over existing history was read in code, not driven.
  • The licensed-program pages beyond the shared engines were not rendered week by week.
  • The RIR scale reference is the commonly used RIR-based RPE convention. Check the exact mapping you want before relabeling.
