Custom workouts save zero sets

Critical · data lossConfirmed by drivingEvery custom workout

I logged every set, tapped the big Finish button, and my history says "0 sets recorded".

Control on run-workout.htmlReads keySets banked

Root cause
run-workout.html has its own finishWorkout(), which reads the set log by card.dataset.id. Phase 2.1 (EN-1/EN-8) moved every logger key to the name-derived nameId(). This one bespoke reader was never updated, so it finds nothing. The page now has two completion controls that disagree, and the larger one is the broken one.
Also wrong
The entry has no id (the sync dedupe key) and no duration. It's added with push() to a newest-first store. It never fires mc:workout-finished, so streak, program progress and the Session Complete recap all skip it. It uses alert(), and the button is 34px tall.
Why no gate saw it
check-journey drives 9 engine pages, none of them this one. The identity test checks PMC pages. Each page passes on its own.
2

Deleted workouts come back

High · broken promiseConfirmed on the real mergeSigned-in users

I deleted that test workout. The dialog said it can't be undone. Next time I opened the app, it was back.

Local after deleteCloud (and last-synced copy)Merged result
[A][A, B][B, A]
Clear All → null[A, B][B, A]
Root cause
mergeWorkoutLog() in mc-sync.js is a pure union. It receives the last-synced copy but ignores it, and deletes are never recorded. deleteFinished() and clearLogs() in workout-logs.html only filter the local copy, so the next pull restores the entry and the next push re-uploads it. The tested mergeArrayByIdTs in the same file already handles deletion records for other stores.

The session screen says the same thing three times

Medium · every setScreenshots + measurementAll program pages

Mid-set I'm hunting for my numbers. There are three timers, buttons I never use, and a red 5×5 that looks like an error.

Evidence
While resting, the screen shows rest time in the toolbar (1:29 REST), in the inline row (1:29 REST REMAINING), and as a 52px Rest: 90 sec chip on the card. The open card also carries a 44px Replace / Reorder row that repeats the ⋯ menu beside it. The prescription pill is red. Completed values are struck through, which makes the number you just lifted harder to read. In light mode the suggested next-set weight measures 1.47:1, which is effectively invisible (.mcl-ghost keeps the dark-mode --ink-8).
Root cause
Each surface was added by a separate, correct change (M3 toolbar, inline rest row, S4 card header), and none of them removed the older one. The ghost rule's comment says the logger "stays dark-styled regardless of html[data-theme]". That stopped being true when the panel picked up light styling. The contrast gate reads text nodes, not input values, so it can't see this.

Targeted action plan

How each pain point gets fixed

These follow the decisions you made in alignment: data integrity first, retire the bespoke Finish, deletes apply everywhere, and all four design tracks are in scope.

1 · Custom workouts: one completion path

  1. Delete run-workout.html's .fw-bar and finishWorkout(). Once the page's own bar is gone, mc-finish.js's inject guard leaves End workout as the only path, the same one custom programs already use correctly.
  2. Confirm getWorkoutName() returns the workout's name. It does today: the driven run banked "Test Push". The custom: true marker can go, because nothing reads it.
  3. Optional recovery: custom entries already saved with 0 sets can be backfilled from mc_setlog_v1, which still holds those sets under x- keys for the last 5 sessions per exercise.
  4. Add a gate: extend the journey run to run-workout.html and run-program.html, finishing through every visible Finish control and asserting the set count saved.

2 · Deletes that stay deleted

  1. Delete and Clear All write a deletion record {id, deleted:true, deletedAt} instead of just filtering the entry out.
  2. Switch mergeWorkoutLog to newest-wins by id, so deletion records carry across devices. Reuse mergeArrayByIdTs's logic, keeping the pageId|date fallback for older entries without an id.
  3. Filter deletion records once, in readWorkoutLog() in mc-log-read.js, which check-single-impl already holds to a single implementation.
  4. The 200 cap counts live entries only. Drop deletion records after 30 days. Add merge cases to test-mc-sync-merge.js.

3 · A calmer session screen

  1. Show one rest readout. Keep the inline row. The toolbar shows elapsed time and sets, and the card's rest chip becomes a small label until the timer starts.
  2. Move Replace and Reorder into the ⋯ menu, freeing a 44px row on every open card.
  3. Make the prescription pill neutral ink and reserve red for failure and destructive actions.
  4. Mark completed values with the check and a row tint, not strikethrough. Give the light-mode ghost value --ink-6: 5.23:1 on cream, computed from the two hex values.

4 · Builder, exercises first

  1. Open on search and muscle filters. Selected exercises gather in the existing review tray.
  2. Ask for the name, program and collection in the tray's Save step, with a suggested name from the main muscles.
  3. Move the page onto the warm ramp and the gold accent. Remove teal, sky blue and the blue header.
  4. Show one exercise count, computed from EXERCISES.length. Raise Share and Start to 44px.

5 · Touch & navigation

  1. Give the hint ✕ a 44×44 hit area (the glyph can stay small), and make the tabs, stats arrows and section links at least 44 tall.
  2. Add those selectors to CHROME_SELECTORS so they're held at 44 from then on.
  3. Use one bottom nav everywhere, with the dashboard's line icons. Decide whether the fifth tab is History or Stats; that's your call.
  4. Move the theme and nutrition icons into the account sheet or an overflow menu, so the greeting fits at 390.

Owner actions (no code)

  1. Add WEEKLY_CHECKIN_SECRET under the repo's Actions secrets, matching the Edge Function's expected value, then trigger the workflow once by hand.
  2. Turn on leaked-password protection in Supabase Auth settings.
  3. Run the real-device checklist: iOS Safari tab, installed PWA, and two signed-in devices for the delete fix.

Proactive design & usability

Design upgrades

Let the number you're about to lift lead

Session

The ghosted suggestion is the most useful number on the screen mid-set. In light mode it's the least legible one. Keep it italic and dashed so it still reads as a suggestion, but at a readable ink:

185 today · 1.47:1 185 proposed --ink-6 · 5.23:1

Use color only where it means something

Visual language

Gold marks what's active or what you can act on. Red means failure or destruction. Everything else is ink. Make the prescription pill, the blue active week tab and the builder's teal and sky-blue labels neutral, so a red element always means something is wrong.

One page title, not two

Hierarchy

workout-logs.html shows "Workout Logs" in the top bar and again as a 36px hero, and the stats page does the same. The heroes push your history and numbers below the first screen. Keep the top bar title, shrink the hero to one line of context, and let the data start higher.

Extend the token gate before migrating

Architecture

P3 established that tokens only reach code that asks for them. Teach check-design-tokens.js to read CSS strings inside mc-*.js, inline <style> blocks, and rgba()/hsl() values. Seed a per-file ratchet at today's counts, then migrate the session surface first (mc-timer.js, mc-finish.js, mc-account.js), measured by luminance as P3 did.

Infer the active program from history

Dashboard

An athlete with a history but no pinned program gets "No active program set". When the last finished workouts belong to a program that has a schedule record, offer it as a one-tap "Continue The Modality Matrix?" instead of an empty state.

See errors from the field

Operations

Let signed-in users send their error buffer, as an opt-in beacon into an insert-only Supabase table, so you learn about crashes before an athlete does. It needs a new table, so it gets its own decision gate, as H3 did.

Method & limits

What was run, and what wasn't

Run in this session

  • Every static gate in CI's list, plus node --check on all tracked JS.
  • Browser gates against a local static server: journey, concurrency, store resilience, crash recovery, exercise identity, PR scope, restore fidelity, contrast light and dark, and a 38-page smoke test.
  • Driven journeys: custom workout (both Finish controls), custom program, rest timer, and a touch-target and type sweep of 13 screens at 390 and 320.
  • mergeStore('workoutLog', …) executed from the real mc-sync.js in a vm sandbox.
  • Supabase security and performance advisors, and the weekly check-in workflow log.

Not verified here

  • Real iOS and Android devices, the installed PWA, and true offline. The service worker only runs on the production origin.
  • Live sign-in and two-device sync. Supabase traffic was blocked in the browser runs.
  • Import over an existing history (read in code, not driven).
  • Browser storage eviction for users who aren't signed in and haven't installed the app. Worth checking against WebKit's current policy.
  • The first-visit timings come from emulated throttling, not a real network.
